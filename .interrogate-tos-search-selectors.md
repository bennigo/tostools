# Destination: device-level selectors for `tos search`

## Problem

Device-level fleet questions require throwaway scripts, and those scripts
silently re-implement TOS semantics — badly. `tos search` can filter the fleet
(`--receiver polarx5`) and project *station* attributes (`--show CODE`), but
nothing that lives on a **device**. Answering "every station's receiver with its
firmware and software version" meant hand-writing `probe_chains.py`, which
embedded three semantic decisions and got two wrong: open-period-only (the bug
that made an earlier sweep miss six stations) and one-receiver-per-marker (which
silently dropped MOHA's second receiver). A CLI that got those right once would
have made both impossible.

## In scope

- **One dotted selector language**, shared by filter and projection:
  `receiver.firmware_version`, `antenna.serial_number`, `*.model`; bare codes
  stay station attributes. Used identically in positional expressions and
  `--show`. `--receiver MODEL` becomes sugar for `'receiver.model ~ MODEL'` and
  keeps working unchanged.
- **Glob/regex matching everywhere**, by wiring the existing
  `_compile_text_pattern` (`tos.py:4360`) into `predicate_matches`
  (`search.py:195`). Substring matching is a subset, so no behaviour change.
- **`--at DATE`** — evaluate as-of a date, default now. The period helper stops
  meaning "the open period" and starts meaning "the period covering D", making
  open-period-only a deliberate default rather than a hidden assumption.
- **`--history`** — cardinality-expanding, one row per period with
  `date_from`/`date_to`. Filters match if **any** period matches (documented in
  `--help`, not configurable).
- **Cache**: on-disk (XDG), keyed by entity id, storing `get_entity_history`
  responses. `--refresh` busts, `--no-cache` bypasses. **Every run prints the age
  of the oldest cache hit it used** — this output drives live TOS writes, so
  staleness must be visible, never inferred.
- **Snapshot pair**: `--snapshot FILE` / `--from-snapshot FILE`, a named dated
  export for reproducibility and audit trails.

## Out of scope

- **Device-rooted search.** `tos search` stays station-rooted; it cannot see
  warehouse stock with no station join. Say so loudly in `--help` — the failure
  mode is reading "47 stations on 5.7.0" as "47 receivers on 5.7.0". A successor
  `tos device search` is planned (e.g. "which stations has this receiver been
  on"); `tos audit timeline` already has the history walk, so it needs mainly an
  enumeration root.
- **Selector-to-selector comparison.** Every predicate compares a selector to a
  literal. Comparing `receiver.firmware_version` against
  `receiver.software_version` needs both a grammar extension and the normalising
  transform (`5.7.0` vs `5.70`), so todo **#145** stays its own piece of work.
- Replacing `tos station show` for the single-station case.
- Any write path. Read-only throughout.

## Definition of done

- `tos search --receiver polarx5 --history --show receiver.firmware_version,receiver.software_version --json`
  yields, for all 103 Septentrio receivers, the same firmware/software period
  sets as `chains_20260822.json` (committed in `gps-tos-corrections f0f295f`) —
  a dated fixture independently produced by the script that drove 101 live TOS
  writes.
- **HVEL, ISAK, KALT, NYLA, SENG, THNA** appear with `--history` and do not
  without it. Their open periods agree while their history diverges; this fails
  loudly if `--history` is quietly evaluating open periods.
- **MOHA shows two receivers.** It has two open `gnss_receiver` joins. Collapsing
  it to one row means the projection inherited the exact defect it exists to
  prevent.

## Hard constraints

- One change per branch, merged to main fast → four branches off `tostools` main.
- No network in tests; `test_search.py`'s `FakeClient` hosts the fixtures.
- No bulk device endpoint exists — device selectors cost `1 + N_children` HTTP
  calls per station (thread-pooled 8-wide, `search.py:426`), ~450 stations.

## Slices

1. **Selector parsing + glob/regex on station attributes.** Device namespace
   parses but errors clearly. Zero behaviour change. Ships
   `tos search 'station_name ~ *vík*'` alone.
2. **Device namespace, open period only.** Filter + project via existing
   `walk_devices`. The tracer bullet. Test: MOHA's two receivers.
3. **Cache + snapshot.** After 2 — nothing worth caching until device walks
   exist; also gives slice 4 a warm loop instead of 20 minutes.
4. **`--at` + `--history`.** Last: multiplies fetch cost, changes cardinality.
   Test: the six history-divergent stations.

`--markers-only` remains, meaningful in limited context.

## Interrogation history (compact)

8 questions, 8 branches resolved. Notable alignment moments:

- **Q2 collapsed three sketched flags into one selector language.** The original
  `--attributes` / `--devices-joined` / `--device-attribute` sketch created two
  vocabularies — flags for device projection, expressions for station filtering —
  with no path to device-attribute *filtering* without inventing a fourth.
- **Q3 made time explicit.** `--at` + `--history` as orthogonal controls, chosen
  over folding time into the selector string, which would hide a cardinality
  change inside a token.
- **Q4 → cache AND snapshot.** Recommendation was snapshot-only (a TTL cache
  hides staleness, and this output drives writes); user required the cache too,
  because searches run in sequence. Reconciled by different granularities plus a
  mandatory cache-age line on every run.
- **Q6 found a golden master already committed.** Done is tied to a byte-
  comparable fixture plus two known-hard cases, not to "the CLI can express it" —
  which can be true while the answer is wrong.
