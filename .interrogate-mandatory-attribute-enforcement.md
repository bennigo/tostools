# Destination: Enforce mandatory TOS attributes at entity-creation time

## Problem

`audit_missing_attributes` detects incomplete TOS entities, but only after the
fact, and nothing runs it at the moment an entity is born. So ISAK's antenna
(installed 2026-07-30) went into TOS without `antenna_reference_point`,
`antenna_offset_north/east` or `azimuth`, and its receiver without `GPS`/`GLO`
constellations — 10 required + 1 recommended gaps across four entities,
undetected until asked for by hand. The catalog already encodes the right rule;
the creation verbs simply never consult it.

## In scope

- Fix **ISAK** to a clean audit — the live test case, via the existing
  `--triage` → `tos audit apply` path, probing the receiver for what it knows
  (constellations).
- Catalog edit: **azimuth → `gps_required_for: [antenna]`** (keeps
  `default_value: "0.0"`, ~95% of azimuths are 0.0, applied automatically).
- **`tostools` primitive** — `check_required(subtype, provided)` sharing the
  exact catalog read `audit_missing_attributes` uses, so gate and audit can
  never disagree.
- **`receivers` wiring** — `cfg replace-antenna` first, then `add-antenna`,
  `add-receiver`, `move-device`.

Three tiers, straight from the catalog:

| tier | rule | example |
|---|---|---|
| required, no `default_value` | **refuse**, naming the attribute | `antenna_reference_point`, `continuity` |
| required, has `default_value` | apply default **and announce it** | `azimuth` → `0.0` |
| `gps_recommended_for` | reminder only | *(now empty — azimuth was the only one)* |

## Out of scope

- The `classification: TODO` axis (inherent/mutable) — feeds the *dates* audit.
- TOS-side web-form validation — not ours.
- The 57 `gps_relevance: no` device codes (seismic/met/hydro).
- `--force` escape hatch on tier-1 refusal — omitted deliberately; added
  preemptively it becomes the default.

## Definition of done

- `tos audit missing-attributes ISAK` exits clean (0 required violations).
- `cfg replace-antenna` refuses on a fixture lacking `antenna_reference_point`,
  naming the attribute and its catalog rule.
- Creating an antenna with no azimuth emits
  `azimuth: applying catalog default 0.0` — a recorded decision, not an accident.

## Hard constraints

- Primitive lives in **`tostools`** (owns catalog, audit, `TOSWriter`);
  `receivers` calls it. Accepts the pin-bump + deploy cost for one rule.
- The **gate ignores audit SUPPRESSes** — silencing a report must not license a
  bad entity.
- `add-antenna --warehouse` runs a **device-scope-only** ruleset (no station
  context).

## Sequencing (tracer bullets, each independently useful)

1. ISAK clean — bgo supplies `continuity` + `antenna_reference_point`.
2. Catalog: azimuth → required.
3. `tostools` primitive + tests → **fable review** (rule engine gating
   production writes).
4. `receivers` wiring, `replace-antenna` first.

## Downstream

No Plan agent, no fable-for-alignment — steps 1–4 *are* the breakdown. Fable
reviews the step-3 primitive once written.

## Interrogation history (compact)

7 questions, 7 branches resolved. Notable alignment moments:

- **Corrected mid-interrogation**: I read "17/95 device codes filled" as 18%
  coverage and recommended deferring the catalog. Wrong — only **one** line
  still carries the `USER FILLS IN` marker; 57 codes are `gps_relevance: no`,
  so empties are deliberate decisions. The catalog is effectively authoritative
  and scope (b) collapsed into (a).
- bgo moved **azimuth from recommended to required-with-default**, on the
  ground that a 95%-dominant default is safe to apply automatically — which is
  a stronger position than "recommended", since the value always gets recorded.
- **Fix-ISAK-before-gate** ordering chosen so the catalog's `suggested:` values
  are validated against a real station before a gate starts refusing work on
  them.
- Two attributes resolve to `<FILL_VALUE>` and cannot be defaulted or probed:
  `continuity` (station) and `antenna_reference_point` (an IGS property of the
  antenna model, not on the receiver).
